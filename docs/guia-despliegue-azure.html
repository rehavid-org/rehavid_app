1. Estado de la suscripción y recuperación

Esta sección conserva los pasos para recuperar la suscripción si Azure vuelve a marcarla como solo lectura. En ese estado no se pueden crear ni modificar recursos.

⚠ Importante Hasta que la suscripción vuelva al estado Enabled, el equipo técnico no podrá crear ni modificar recursos.

Pasos para reactivar la suscripción

  1. Ingresar al portal de Azure
    Abra https://portal.azure.com en su navegador e inicie sesión con la cuenta de administrador.
  2. Abrir el menú de suscripciones
    En la barra lateral izquierda haga clic en Subscriptions (Suscripciones). Si no lo ve, escriba "subscriptions" en el cuadro de búsqueda superior.
  3. Seleccionar la suscripción
    Haga clic en Azure subscription 1 (o el nombre que aparezca).
  4. Revisar el mensaje de advertencia
    En la parte superior aparecerá una franja de color con la razón por la que está deshabilitada. Léala con atención.
  5. Aplicar la solución según el caso
    • Saldo vencido: vaya a Billing > Payment methods > Pay now y pague el monto pendiente.
    • Límite de gasto alcanzado: elimine el límite de gasto o actualice a Pay-As-You-Go.
    • Deshabilitada manualmente: haga clic en Re-enable o Activate.
  6. Esperar la propagación del cambio
    El estado puede tardar entre 2 y 5 minutos en actualizarse en el portal.
  7. Verificar el estado
    El estado de la suscripción debe mostrar Enabled. Cuando vea esa palabra, la suscripción ya permite crear recursos.
¿Por qué importa este paso? Azure bloquea cualquier acción que genere costos cuando una suscripción está deshabilitada. Reactivarla es como encender la llave general de la electricidad: sin ella, ningún equipo nuevo puede funcionar.

2. Creación del servidor (VPS)

Una vez la suscripción esté activa, el equipo técnico creará la infraestructura. A continuación se explica qué se va a crear y por qué cada pieza es necesaria.

  • Máquina virtual (rehavid-vm) Es el computador que estará encendido las 24 horas en la nube de Microsoft. Allí se ejecutará la aplicación Django.
  • Red virtual (rehavid-vnet) Es una red privada que aísla el servidor de otros clientes de Azure. Aislarlo reduce la superficie de ataque y mejora la seguridad.
  • Grupo de seguridad (rehavid-nsg) Es el cortafuegos. Solo permitirá tráfico por los puertos 22 (acceso técnico), 80 (web normal) y 443 (web segura con HTTPS).
  • Dirección IP pública (rehavid-ip) Es la dirección visible desde Internet. Es como el número de casa del servidor: cuando alguien escribe el dominio, termina llegando aquí.
  • Ubuntu Server 24.04 LTS Es el sistema operativo. Es equivalente a Windows, pero diseñado para servidores: más ligero, estable y seguro para este tipo de aplicaciones.

Cómo se conectan las piezas

Todo en un solo servidor La aplicación, la base de datos (PostgreSQL), la cola de tareas (Redis) y los procesos en segundo plano (Celery) corren juntos dentro del mismo servidor usando Docker Compose. Esto simplifica la infraestructura, reduce costos y facilita el mantenimiento. El equipo técnico se encarga de crear estos recursos mediante scripts automatizados — usted solo necesita una suscripción activa.

3. Qué necesita tener listo el cliente

Antes de que el equipo técnico comience, revise que cuente con cada uno de estos elementos:

  • Suscripción de Azure reactivada (ver sección 1).
  • Acceso al portal de Azure con una cuenta que tenga permisos de administrador.
  • Un método de pago vigente vinculado a la suscripción.
  • Dominio rehavidapps.com.co configurado y protegido con HTTPS.
⚠ Recuerde Si falta alguno de estos elementos, el despliegue se detendrá y deberá esperar hasta resolverlo.

4. Próximos pasos después del servidor

Cuando la máquina virtual ya exista, el equipo técnico continuará con la instalación y configuración interna.

  1. Instalar Docker
    Docker es la herramienta que permite ejecutar toda la aplicación dentro de "contenedores" — paquetes aislados que incluyen todo lo necesario para funcionar. Se instala una sola vez en el servidor.
  2. Levantar todos los servicios con Docker Compose
    Con un solo comando se inician juntos: la aplicación web (Django), la base de datos (PostgreSQL), la cola de tareas (Redis) y los trabajadores en segundo plano (Celery). Todo corre dentro del mismo servidor, aislado en contenedores.
  3. Verificar el dominio
    El dominio rehavidapps.com.co apunta a la IP pública del servidor (20.119.43.198) y www es un alias del dominio principal.
  4. Verificar el certificado SSL
    HTTPS está activo con un certificado de Let's Encrypt para rehavidapps.com.co y www.rehavidapps.com.co.

5. Preguntas frecuentes

¿Por qué se deshabilitó mi suscripción?
Las causas más comunes son: saldo vencido, haber alcanzado el límite de gasto de una prueba gratuita, o que un administrador la haya pausado manualmente.
¿Cuánto cuesta el servidor?
Para una máquina estándar como Standard_B2s, el costo aproximado es de 20 a 30 USD mensuales, dependiendo del tráfico y del almacenamiento adicional.
¿Qué pasa si apago el servidor?
La aplicación dejará de estar disponible en Internet, pero los datos almacenados en los discos se conservan. Cuando se vuelva a encender, todo seguirá donde estaba.
¿Necesito hacer algo después del despliegue?
No. Una vez configurado, el sistema requiere solo el pago mensual de Azure. El equipo técnico se encarga de mantenimientos y actualizaciones cuando sean necesarios.
